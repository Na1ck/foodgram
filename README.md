# Foodgram

## Описание

Foodgram — это платформа для рецептов! Приложение позволяет пользователям делиться раличными рецептами.

**Основные возможности:**
*   **Просмотр рецептов:** На главной странице отображаются рецепты, добавленные пользователями.
*   **Создание рецептов:** Зарегистрированные пользователи могут добавлять новые рецепты, указывать время приготовления, добавлять ингрединты и загружать фотографию рецептф.
*   **Редактирование рецептов:** Авторы могут редактировать информацию о своих рецептах.
*   **Подписки:** Зарегестрированные пользователи могут подписываться на авторов рецептов.
*   **Избранное:** Зарегестрированные пользователи могут добавлять рецепты в избранное, чтобы их не потерять.
*   **Список покупок:** Зарегестрированнеы пользователи могут скачивать список покупок в формате .txt, в нем будут все нужные ингредиенты из рецептов для покупки

Просматривать рецепты могут все посетители, а для добавления и редактирования требуется регистрация.

## Необходимые инструменты

Для запуска проекта локально на вашей машине должен быть установлен:
*   **Docker** (версия 20.10.0 или выше)
*   **Docker Compose** (версия 2.0.0 или выше)

## Инструкция по установке и запуску

1.  **Клонируйте репозиторий:**
    ```bash
    https://github.com/Na1ck/foodgram.git
    cd foodgram
    ```

2.  **Создайте и настройте файл `.env`:**
    Создайте в корне проекта файл `.env` на основе примера (например, `.env.example`) и заполните все необходимые переменные окружения. Файл будет использоваться всеми сервисами.
    *Пример необходимых переменных:*
    ```bash
    POSTGRES_DB=foodgram
    POSTGRES_USER=user
    POSTGRES_PASSWORD=password
    DB_NAME=foodgram
    DJANGO_KEY=key
    DJANGO_DEBUG=False
    DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1
    HOST_PORT=8080
    CONTAINER_PORT=80
    ```

3.  **Соберите и запустите контейнеры:**
    ```bash
    docker compose up --build
    ```

4.  **Примените миграции базы данных:**
    После запуска контейнеров, в отдельном терминале выполните:
    ```bash
    docker compose exec backend python manage.py migrate
    ```

5.  **Соберите статические файлы:**
    ```bash
    docker compose exec backend python manage.py collectstatic --noinput
    ```

После выполнения этих шагов приложение будет доступно по адресу: `http://localhost`

## CI/CD (GitHub Actions Workflow)

В проекте настроен автоматический пайплайн развертывания. При пуше в ветку `main` происходят следующие этапы:

1.  **Запуск тестов:** Проверка кода бэкенда и фронтенда.
2.  **Сборка и публикация Docker-образов** на Docker Hub для всех сервисов.
3.  **Деплой на сервер:** Автоматическое обновление контейнеров на production-сервере.

## Стек технологий

- **Pillow 11.3.0** - работа с изображениями

### Frontend
- **React** - пользовательский интерфейс

### Infrastructure
- **Docker** + **Docker Compose** - контейнеризация
- **Nginx** - веб-сервер

### DevOps
- **GitHub Actions** - CI/CD пайплайн
